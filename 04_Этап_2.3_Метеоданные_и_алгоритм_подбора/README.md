# Этап 2.3: Метеоданные и логика интеллектуального подбора

## 1. Метеорологический сервис (WeatherService)
- Выполняет асинхронные HTTP GET-запросы к бесплатному открытому API Open-Meteo (`https://api.open-meteo.com/v1/forecast`);
- Поддерживает геокодирование городов (СПб, Москва, Новосибирск и др.) и коррекцию часовых поясов;
- Извлекает: ощущаемую температуру (`apparent_temperature`), скорость ветра (`wind_speed_10m`), вероятность осадков (`precipitation_probability`);
- Обеспечивает **автономный режим** при отсутствии интернета: пользователь задает температуру, осадки и ветер вручную.

## 2. Алгоритм подбора одежды (OutfitRecommendationEngine)
- **Температурный комфорт:** расчет эффективной ветро-холодовой температуры:
  $$T_{eff} = T_{feels} - 0.7 \cdot V_{wind}$$
  Определение теплового класса: лёгкая ($>18^\circ$C), демисезонная ($8..18^\circ$C), тёплая ($-2..8^\circ$C), зимняя ($<-2^\circ$C).
- **Правило влагозащиты:** при $P_{precip} \ge 30\%$ обязательна водостойкая верхняя одежда/обувь или зонт.
- **Форматы активности (дресс-код):** фильтрация по событиям: «учёба», «работа», «свидание», «прогулка», «спортзал».
- **Генерация 3 вариантов:** Сбалансированный, Утепленный/защищенный, Альтернативный образ.
- **Связные объяснения:** генерация человекочитаемого текста с обоснованием логики выбора.
- **Диагностика дефицита:** точный список недостающих категорий при нехватке вещей.

## 3. Состав файлов этапа
